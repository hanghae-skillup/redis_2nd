# 성능 테스트 보고서
`5분간 최대 최대 1000명의 가상 사용자(VU)가 참여한다는 가정하에 테스트 진행했습니다`

## 1. Index 적용 전(검색 조건 없음)
### 쿼리(실제 동작 하는 쿼리)
```
select 
	t.name, 
    m.title, m.grade, m.release_date, m.thumbnail_url, m.running_time, m.genre,
    s.screen_number, s.start_time, s.end_time
from theater t
join screening s
on t.id = s.theater_id
join movie m
on s.movie_id = m.id
     -- where m.title ='타이타닉'
     -- and m.genre = 'ROMANCE'
order by m.release_date asc, s.id asc, s.start_time asc
```
### 실행 계획
- pk 이외에 index가 없기에 theater, screening 테이블은 full scan이 발생하고 있다
![검색조건적용전.png](/docs/images/인덱스적용전_실행계획.png)

### 부하테스트 결과
- 평균 요청 처리 시간 : 33.77s
- 평균 요청 실패율 : 10.99%
  - 슬로 쿼리로 인한 커넥션 고갈로 인해서 아닐까 예상
- 동시에 활성화된 가상 사용자 : 518
![검색조건적용전.png](/docs/images/검색조건적용전.png)

## 2. Index 적용 후
### = 실행 계획
- 영화 제목 index에 해당되는 idx_title 적용
- 영화 id, 상영 시간 순으로 정렬하도록 index 적용
![인덱스적용_영화제목_동등검색_실행계획.png](/docs/images/인덱스적용_영화제목_동등검색_실행계획.png)

### like 실행 계획
- 영화 제목 like 검색으로 인하여 영화 제목 idx_title가 적용 안되고 있음
- 영화 장르 인덱스 idx_genre 가 적용됨
- 영화 id, 상영 시간 순으로 정렬하도록 index 적용
![인덱스적용_영화제목_like검색_실행계획.png](/docs/images/인덱스적용_영화제목_like검색_실행계획.png)

### 부하테스트 결과

- 평균 요청 처리 시간 : 7.91s

- 동시에 활성화된 가상 사용자 : 34
